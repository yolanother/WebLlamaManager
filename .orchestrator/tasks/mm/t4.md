# Bare /v1 aliases + server-side multimodal expansion in chat/completions

## Goal
(a) Serve the OpenAI routes at bare `/v1/*` as well as `/api/v1/*`, and (b) expand
`video_url` / `audio_url` content parts server-side so an API client can pass a
YouTube link directly to `chat/completions`.

## Why
A stock OpenAI SDK pointed at this server 404s: routes mount only at `/api/v1`
and there is no rewrite, so a bare `/v1` POST falls through to the GET-only SPA
catch-all (`api/server.js:9512`). Separately, video/YouTube support today lives
entirely in the browser — the Chat UI calls `/api/media/*`, pulls frames back, and
base64s them client-side — so agents cannot use it at all. This task is the single
biggest win for the stated goal.

## Depends on

## What to build
1. **Aliases**: extract each OpenAI handler to a named function and register it at
   both `/api/v1/...` and `/v1/...`. Do **not** use a redirect — it breaks POST
   bodies and streaming. Do not duplicate handler logic.
2. **`expandMessages(messages, opts)`** → `{ messages, media[], warnings[] }`:
   - Walks content arrays; leaves standard `text` / `image_url` / `input_audio`
     parts untouched (zero behaviour change for existing clients).
   - `video_url` → ingest via the media pipeline → `[video: …]` text marker + N
     `image_url` parts each preceded by `[frame n/N @ MM:SS]` + `input_audio` parts
     when `include_audio` (default true).
   - `audio_url` → ingest → `input_audio`.
   - Honours `max_frames`, `include_audio`, `start`, `end`.
   - Media longer than one window uses the segment-and-summarize path (design doc
     §5.2): per-window internal digest completions, then a `[media digest: <name>]`
     text part plus representative frames spanning the full duration.
   - Caches by URL so a repeated link in a conversation is not re-downloaded.
3. Report what happened in the response as
   `metadata.llama_manager_media = { items: [{ id, kind, durationSec, windows, framesUsed, digested }] }`.
   Never silently drop content.

## Public surface changes

- New response field `metadata.llama_manager_media`.
