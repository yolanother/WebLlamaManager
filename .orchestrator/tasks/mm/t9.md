# /docs update + live end-to-end verification against real Gemma-4

## Goal
Document the shipped multimodal API under `/docs`, sync it to knowledge, and prove
the whole path works against a real Gemma-4 load on the box.

## Why
This is the task that de-risks the single largest unknown in the design: whether
llama.cpp actually loads the mmproj **audio** encoder in `--models-dir` router mode.
`docs/llama-cpp-rocm-build-and-deployment.md:133-152` states `--models-dir` cannot
express per-model options and that mmproj works only by router auto-detection.
Nothing about audio has ever run on this box.

## Depends on
The expansion, capability, transcriptions, and API-docs-page tasks.

## Verification to perform (live, on this box)
Operator has approved loading Gemma-4. **DS4 stays resident — do not unload it.**

1. Load a Gemma-4 model with an mmproj present and confirm from the llama.cpp
   startup log that **both** the vision and audio encoders initialise.
2. Image: a `chat/completions` request with an `image_url` part returns a correct
   description.
3. Audio: a short WAV as `input_audio` returns a correct answer. **This is the
   make-or-break check.**
4. Video with sound: a short local MP4 via `video_url` returns an answer that
   references something only audible, proving audio actually reached the model.
5. YouTube: a short link via `video_url` in a single `chat/completions` call.
6. Long media: a >1-window source exercises the digest path; confirm
   `metadata.llama_manager_media` reports `digested: true`.
7. `POST /v1/audio/transcriptions` returns sensible text.
8. Stock OpenAI SDK against `base_url=http://localhost:5250/v1`.
9. `curl -s http://localhost:5250/llms.txt` returns markdown.

**If the audio encoder does not load in router mode**, fall back to
`--models-preset` with `LLAMA_ARG_MMPROJ` per the reference above, document the
required configuration precisely, and record it in `docs/GOTCHAS.md`.

## What to document
The content-part contract (standard + extensions), the YouTube path, limits
(window length, frame cap, 720p ceiling, 200 MB body cap), the digest reporting
contract, capability discovery via `modalities` on `/v1/models`, the `/v1` vs
`/api/v1` base URLs, and the doc URLs. Then run `orch docs sync --json`.
