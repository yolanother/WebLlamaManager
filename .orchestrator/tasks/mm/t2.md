# Single-source API spec module + OpenAPI generator

## Goal
Create `api/api-spec.js` as the one description of every endpoint this server
serves, plus a script that regenerates `api/openapi.json` from it.

## Why
There are three drifting descriptions of the API today: a hardcoded array in
`ui/src/pages/ApiDocs.jsx:253-320` listing only 4 OpenAI endpoints, a stale
`api/openapi.json` (last touched Feb 19, missing `/api/media/*`, `/api/backends/*`,
`/api/ds4/*`, `/api/queue/*`, `/api/analytics/*` entirely), and a hand-maintained
map in `GET /api/info`. Everything downstream — the docs page, `llms.txt`, the
OpenAPI file — must come from one array or it will drift again.

## Files to touch
- `api/api-spec.js` (new)
- `api/api-spec.test.js` (new)
- `scripts/gen-openapi.mjs` (new)

Do **not** touch `api/server.js` or `api/openapi.json` — later tasks consume this.

## Reference files
- `api/server.js` route inventory — the full list is enumerated in the epic's recon
  and in the design doc; the authoritative source is the `app.get/post/put/delete`
  calls in `api/server.js`. Cover **every** route, not just the OpenAI ones.
- `api/openapi.json` — current (stale) shape to stay broadly compatible with.
- `api/server.js:6405-6434` `GET /api/info` — the existing agent-facing blob.
- Design doc §5.6.

## What to build
`ENDPOINTS`: an array of
`{ method, path, summary, description, tags, params[], requestSchema,
responseSchema, examples[] }`, where each example is
`{ title, body, curl, python, javascript }`.

Requirements:
- Cover every route the server actually serves, grouped by tag (openai, media,
  models, presets, backends, queue, analytics, logs, system).
- Record that OpenAI routes are served at **both** `/api/v1/...` and `/v1/...`
  (the alias task adds the latter) and that the documented base URL is
  `http://<host>:5250/v1`.
- Include the full multimodal content-part contract from design doc §4 as
  structured data — standard `text` / `image_url` / `input_audio` parts plus the
  `video_url` / `audio_url` extensions — with at least one worked YouTube example.
- `scripts/gen-openapi.mjs` writes a valid OpenAPI 3.1 document from `ENDPOINTS`.
- A test asserts the generated document validates structurally and that every
  `ENDPOINTS` entry has a non-empty summary and at least one example.

## Public surface changes
New module `api/api-spec.js` exporting `ENDPOINTS` (and any helper the generators
need). New script `scripts/gen-openapi.mjs`.

## Acceptance criteria
- [ ] `node scripts/gen-openapi.mjs` emits a valid OpenAPI 3.1 doc to stdout or a path.
- [ ] Test asserts every entry has summary + ≥1 example, and that the multimodal
      part contract is present.
- [ ] Endpoint count is materially greater than the 24 paths in the stale file.
- [ ] `./scripts/dev-build.sh check` and `container` pass.

## Out of scope
Serving anything over HTTP; editing the UI; overwriting `api/openapi.json` (a later
task does the regen + commit).
