# Audio ingestion + long-media segmentation in the media pipeline

## Goal
Teach `api/media.js` to accept and process **audio**, extract an audio track from
video/YouTube sources, and add a window planner for long media.

## Why
`sniffMediaType()` currently hard-rejects every non-image/video MIME
(`api/media.js:257`, `:298`), and frame extraction discards audio via `-an`
(`api/media.js:552`). Gemma-4's mmproj has a real audio encoder, so this is the
one change that unlocks both audio input and sound-aware video.

## Files to touch
- `api/media.js` (extend)
- `api/media.test.js` (extend)
- `api/media-segments.js` (new)
- `api/media-segments.test.js` (new)

Do **not** touch `api/server.js` — a later task mounts everything.

## What to build
1. Magic-byte sniffing for `wav` (RIFF…WAVE), `mp3` (ID3 / 0xFFFB), `flac` (fLaC),
   `ogg` (OggS), `m4a` (ftyp…M4A). Extend `MIME_EXTENSIONS` to match.
2. `extractAudio()` — `ffmpeg -vn -ac 1 -ar 16000 -c:a pcm_s16le` producing 16 kHz
   mono WAV. That is what the Gemma audio tower expects.
3. Video sources gain audio extraction as a **separate ffmpeg invocation**. Leave
   `-an` on the existing frame command untouched — do not regress the frame path.
4. `api/media-segments.js`: `planSegments(durationSec, opts)` returning fixed
   windows (default 600 s, from `LLAMA_MANAGER_MEDIA_WINDOW_SEC`), each with
   `{ index, startSec, endSec, frameTimestamps }`. Pure function, no I/O — it must
   be trivially unit-testable.
5. New routes on the media router: `GET /api/media/:id/audio/:n.wav`. Metadata from
   `GET /api/media/:id` gains `audio: { segments, durationSec, sampleRate, channels }`.
6. Honour the existing bounds (20 items LRU, 250 MB) and the 501-with-hint
   degradation when binaries are absent.

## Public surface changes
- New exports from `api/media.js`: `extractAudio`.
- New module `api/media-segments.js` exporting `planSegments`.
- New route `GET /api/media/:id/audio/:n.wav`; `audio` key added to media metadata.

- [ ] Tests cover: each audio magic-byte type; audio extracted from an MP4; a

- [ ] Existing `api/media.test.js` cases still pass unchanged.
- [ ] Frame extraction output is byte-for-byte unchanged for an image and a short video.
