# API Docs page: spec-driven, multimodal, with runnable examples

## Goal
Rebuild `ui/src/pages/ApiDocs.jsx` to render from the shared API spec, document
multimodal usage properly, and make the examples executable.

## Why
The page hardcodes its endpoint list in a JS array and shows only 4 OpenAI
endpoints out of ~70 (`ui/src/pages/ApiDocs.jsx:253-320`). It has no multimodal
content whatsoever, renders curl into a raw `<pre>` with no highlighting, and
offers no python/javascript examples. It also can't drift-check itself.

## Depends on
The llms.txt/openapi task (so the spec is complete and servable).

- `ui/src/pages/ApiDocs.jsx`
- `ui/src/styles/pages.css`

## What to build
1. Drive the endpoint list from the shared spec (fetch the served spec/openapi
   rather than re-hardcoding; if a build-time import is simpler, ensure there is
   exactly one source of truth and no second copy of the endpoint list).
2. A **Multimodal guide** section covering, with runnable examples: images (data URL
   and http URL), audio via `input_audio`, video files, and **YouTube links via
   `video_url`** — plus the documented limits and the digest behaviour for long media.
3. curl / python / javascript tabs per example, rendered through `CodeBlock` with
   syntax highlighting and copy.
4. Prefill multimodal example bodies into the existing "Send Request" tester so the
   documented examples can be executed in place. Keep the existing model dropdown
   (`SearchableSelect` fed by `/v1/models`) and show each model's `modalities`.
5. Link prominently to `/llms.txt`, `/llms-full.txt`, and `/api/openapi.json`.
6. Keep the two-pane layout and responsive behaviour; match the existing glass styling.
