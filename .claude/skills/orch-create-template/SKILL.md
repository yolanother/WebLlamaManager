# Create Template from Project Analysis

Analyze an existing project's documentation, design files, setup, and code structure to automatically generate a project template definition that can be registered with the orchestrator.

## Process

### 1. Gather Project Context

Analyze the project to understand its architecture, dependencies, and configuration:

```bash
# Check project structure
ls -la
ls docs/ docs/Designs/ 2>/dev/null

# Check package configuration
cat package.json 2>/dev/null || cat Cargo.toml 2>/dev/null || cat pyproject.toml 2>/dev/null

# Check for existing CLAUDE.md / instruction config
cat CLAUDE.md 2>/dev/null
cat .claude/settings.json 2>/dev/null

# Check frameworks and languages
find . -maxdepth 3 -name "*.ts" -o -name "*.tsx" -o -name "*.py" -o -name "*.rs" -o -name "*.go" | head -20

# Check for Docker / CI setup
ls Dockerfile docker-compose.yml .github/workflows/ 2>/dev/null
```

### 2. Identify Feature Packages

Check which orchestrator feature packages are already installed or would be needed:

```bash
orch features installed --json 2>/dev/null
orch features list --json 2>/dev/null
```

Map the project's capabilities to available feature packages. For each feature found:
- Note the slug
- Determine if it's required or optional
- Extract any custom configuration

### 3. Analyze Compatibility

Determine the frameworks and languages used:

- **Frameworks**: React, Next.js, Vue, Svelte, Express, Fastify, Flask, Django, Axum, etc.
- **Languages**: TypeScript, JavaScript, Python, Rust, Go, etc.
- **Build tools**: Vite, Webpack, esbuild, Cargo, Poetry, etc.

### 4. Extract Design Defaults

Look for:
- UI conventions (component libraries, CSS framework)
- Code conventions documented in CLAUDE.md or design docs
- Testing patterns
- Directory structure conventions

### 5. Identify Scaffolding

If the project was scaffolded from a repo or has a standard file structure:
- Note the repo URL if available (check git remote)
- Map the file structure pattern
- Identify initialization commands (from README, Makefile, or scripts)

### 6. Generate Base Prompt

Create a comprehensive markdown base prompt that describes:
- What the template builds
- Architecture overview
- Key design decisions
- How to extend it
- Common customization points

### 7. Build Template Definition

Assemble the template definition JSON:

```json
{
  "slug": "<auto-generated-from-name>",
  "name": "<Template Name>",
  "description": "<One-line description>",
  "category": "<web|api|cli|mobile|desktop|full-stack|library|devops>",
  "tags": ["<relevant>", "<tags>"],
  "basePrompt": "<markdown content from step 6>",
  "definition": {
    "featurePackages": [
      { "slug": "<feature-slug>", "required": true/false, "defaultConfig": {} }
    ],
    "instructionProfile": {
      "blocks": [
        { "sectionSlug": "<section>", "enabled": true, "sortOrder": 1 }
      ],
      "toolTarget": "claude"
    },
    "projectDefaults": {
      "defaultModelTier": "standard",
      "defaultTargetBranch": "main"
    },
    "scaffolding": {
      "repoUrl": "<if available>",
      "fileStructure": ["<key directories>"],
      "initCommands": ["<setup commands>"]
    },
    "designDefaults": {
      "conventions": "<coding conventions>",
      "uiKit": "<UI library if applicable>"
    },
    "compatibility": {
      "frameworks": ["<detected frameworks>"],
      "languages": ["<detected languages>"]
    }
  }
}
```

### 8. Register Template

Write the definition to a temp file and create via API:

```bash
# Write definition
cat > .orchestrator/tasks/template-def.json << 'TEMPLATE_EOF'
{ ... template JSON ... }
TEMPLATE_EOF

# Create template
orch templates create "<name>" --file .orchestrator/tasks/template-def.json --json
```

Or if the user prefers, create it via the web UI by showing the JSON for copy-paste.

## Output

Present the generated template to the user for review before registering:
1. Show the template name, description, and category
2. List detected feature packages (required vs optional)
3. Show compatibility info (frameworks, languages)
4. Display the base prompt preview
5. Show scaffolding details
6. Ask for confirmation before creating

## Tips

- Be conservative: only include features that are clearly present in the project
- The base prompt should be detailed enough for an agent to understand how to work in the template
- Include setup/init commands from README or Makefile
- Check `git remote -v` for the scaffolding repo URL
- Look at `docs/Designs/` for architectural context to include in the base prompt
